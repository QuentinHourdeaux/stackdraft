# Planned PR 19 — v0.1 Real-use Evaluation

Depends on Planned PR 18.

## Required context

Read `docs/implementation-contract.md`, the v0.1 acceptance criteria, and the
complete `docs/project-evolution.md`.

## Outcome

Determine whether Stackdraft v0.1 has become the natural place to capture and
review personal engineering work.

## Included

- Use Stackdraft for at least five working days across normal personal
  engineering work, including small standalone features, bugs, investigations,
  and passing development intent that might otherwise go into a temporary note.
- Record moments where another note, document, or tracker is used instead.
- Record capture friction, missing context, confusing language, and reliability
  problems in `project-evolution.md`.
- Record when a Stack is created because related Drafts genuinely benefit from
  shared context versus when the product appears to pressure the user into
  creating one.
- Confirm backup confidence and use from another computer on the trusted local
  network when available.
- Mark the v0.1 specification as validated when its final acceptance criterion
  is met.

## Not included

- Bundling discovered feature work into an evaluation PR
- Pipeline, Delivery, Trace, GitHub, or AI features
- Cosmetic changes without observed usability impact

## Fixed implementation details

- This is an evaluation and documentation PR, not automatically a code PR.
- If a blocking defect or narrowly missing v0.1 behavior is found, add a new
  specifically scoped planned-PR file before this one, implement it separately,
  and restart or extend the affected part of the evaluation.
- Feature ideas beyond v0.1 are recorded as product observations, not silently
  added to the v0.1 scope.
- Evidence should summarize actual use without becoming a chronological diary of
  every click.
- Begin normal capture without pre-creating organizational structure. The
  evaluation must not manufacture Stack usage to demonstrate the feature.
- Treat any need to create or choose a Stack before capturing an ordinary Draft
  as blocking v0.1 friction, not as a user-training problem.

## Acceptance

- Stackdraft was used for at least five working days.
- The user chose it over temporary notes for quick standalone and normal
  development-work capture.
- Stacks were optional: they were used only where organization added value, and
  Draft workflows remained natural when no Stack was involved.
- No known issue blocks continued personal use.
- Important friction and follow-up ideas are preserved in the evolution record.
- `docs/v0.1-spec.md` accurately states the validation outcome.
- `deno task ci` still passes.

## Completion signal

Delete this file in the evaluation PR. If no newly planned files remain, remove
the empty `docs/planned-prs/` directory and treat v0.1 as validated.
